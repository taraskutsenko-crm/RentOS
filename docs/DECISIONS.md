# RentOS Decision Register

A concise index of major repository decisions. Full rationale for
schema/architecture-level decisions lives in the linked ADRs
(`docs/adr/`) — this file does not repeat their content, only points to
it, plus records the many smaller decisions that never warranted a full
ADR of their own.

| ID    | Decision                                                                                                                                                                                                                                                                                                 | Reason                                                                                                                                                                                                                                                                                                                                         | Status                                    | Reference                                                                                                                                              |
| ----- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------ |
| D-001 | Multi-tenancy: single shared database, `tenantId` column on every tenant-scoped table, membership re-verified server-side on every request                                                                                                                                                               | Simplest operational model for the current scale; avoids schema/database-per-tenant operational overhead while keeping isolation structurally enforced, not filter-remembered                                                                                                                                                                  | Accepted                                  | [ADR 0001](adr/0001-authentication-and-tenant-context.md)                                                                                              |
| D-002 | RBAC via granular, named permissions (`"<resource>.<verb>"`) checked by a shared `PermissionsGuard`, never role-name checks in controllers                                                                                                                                                               | Keeps authorization centrally auditable and independently testable; a role's meaning can change without touching every controller                                                                                                                                                                                                              | Accepted                                  | `apps/api/src/permissions/permission.ts`; every module's e2e permission-matrix tests                                                                   |
| D-003 | Prisma + PostgreSQL as the only persistence layer                                                                                                                                                                                                                                                        | Strong migration tooling, transactional guarantees needed for numbering/pricing correctness, team familiarity                                                                                                                                                                                                                                  | Accepted                                  | `apps/api/prisma/schema.prisma`                                                                                                                        |
| D-004 | Money stored as integer minor currency units + ISO 4217 currency code; percentages as integer basis points; no `Decimal` library                                                                                                                                                                         | Eliminates floating-point drift entirely rather than managing it; simpler mental model than a Decimal type for this codebase's needs                                                                                                                                                                                                           | Accepted                                  | [ADR 0002](adr/0002-universal-asset-model.md), [ADR 0007](adr/0007-quotes-and-commercial-offers.md)                                                    |
| D-005 | Timestamps (`DateTime`), not date-only columns, for planned/actual rental and quote dates; all calendar-month arithmetic pinned to UTC fields                                                                                                                                                            | Rentals/quotes can start/end at a specific time of day, not just a calendar date; UTC-only arithmetic avoids host-timezone-dependent bugs in month/day-boundary math                                                                                                                                                                           | Accepted                                  | [ADR 0008](adr/0008-configurable-monthly-billing-strategies.md)                                                                                        |
| D-006 | Server-authoritative pricing: client-side pricing utilities are estimate-only and never trusted for a persisted total                                                                                                                                                                                    | Prevents client tampering and client/server drift; the server is the only place totals are computed and stored                                                                                                                                                                                                                                 | Accepted                                  | `apps/api/src/rentals/rental-pricing.util.ts`, `apps/api/src/quotes/quote-pricing.util.ts`; every `lib/*-pricing.ts` file's doc comment                |
| D-007 | Historical pricing snapshots: `RentalItem`/`QuoteItem` freeze the monthly-billing strategy they were priced under; a later tenant-settings change never retroactively changes stored totals                                                                                                              | A rental/quote's price must remain exactly what was charged/quoted regardless of later configuration changes — a hard product requirement, not just an engineering nicety                                                                                                                                                                      | Accepted                                  | [ADR 0008](adr/0008-configurable-monthly-billing-strategies.md)                                                                                        |
| D-008 | Three tenant-configurable monthly billing strategies (`CALENDAR_MONTH` default / `FIXED_30_DAYS` / `CUSTOM`), replacing a single hardcoded whole-month-rounding rule                                                                                                                                     | Different rental businesses define "one month" differently for billing purposes; a single hardcoded rule couldn't serve all of them                                                                                                                                                                                                            | Accepted (Rentals and Quotes — see D-013) | [ADR 0008](adr/0008-configurable-monthly-billing-strategies.md), [ADR 0009](adr/0009-shared-monthly-pricing-and-atomic-rental-numbering.md)            |
| D-009 | Universal asset model: one `Asset` schema for every rental industry, type-specific attributes via tenant-defined custom fields, never schema columns                                                                                                                                                     | Core product bet — see [VISION.md](VISION.md)                                                                                                                                                                                                                                                                                                  | Accepted                                  | [ADR 0002](adr/0002-universal-asset-model.md)                                                                                                          |
| D-010 | Every create/update/delete/status-change/settings-change writes an `AuditLog` row, scrubbed of secrets, written in the same transaction as the action where the action is transactional                                                                                                                  | Traceability for a multi-tenant SaaS handling commercial data; a requirement independent of any specific module                                                                                                                                                                                                                                | Accepted                                  | `apps/api/src/audit/`                                                                                                                                  |
| D-011 | Localization via `i18next` + one JSON resource file per language, key-parity verified across all six shipped languages on every task                                                                                                                                                                     | Multilingual from day one is a stated product principle, not a follow-up; drift is caught before merge rather than discovered in production                                                                                                                                                                                                    | Accepted                                  | `packages/localization/`, [PRODUCT_PRINCIPLES.md](PRODUCT_PRINCIPLES.md)                                                                               |
| D-012 | Manual, scripted Docker Compose verification (build the full stack, apply migrations, drive the real browser) is required before every task is considered done, in addition to automated tests                                                                                                           | Automated tests don't catch container-build issues, ESM/CJS interop bugs, or genuine end-to-end UX problems — all of which have been caught this way in past tasks (e.g. the `with { type: "json" }` import-attribute bug)                                                                                                                     | Accepted                                  | Every completed task's manual-verification section                                                                                                     |
| D-013 | Quotes' `MONTHLY` pricing shares Rentals' pricing engine and tenant billing settings (`RentalBillingSettings`) rather than maintaining a separate implementation or a separate settings model                                                                                                            | Both Rentals and Quotes bill `MONTHLY` line items the same way from a business perspective; a tenant should configure this once, not per-module. `RentalBillingSettings` keeps its existing name (a cosmetic mismatch, not a functional one) rather than forcing a risky rename of an already-shipped model, permission set, and settings page | Accepted                                  | [ADR 0009](adr/0009-shared-monthly-pricing-and-atomic-rental-numbering.md)                                                                             |
| D-014 | Quote-to-rental conversion carries over each `ASSET` `QuoteItem`'s frozen `monthlyBillingStrategy`/`customMonthLengthDays` onto the resulting `RentalItem`, but the Rental's own totals continue to be copied verbatim from the Quote's authoritative totals (unchanged from ADR 0007), never recomputed | Keeps the already-accepted commercial number the customer agreed to, while still letting the resulting Rental's item-level breakdown display correctly and reproducibly after conversion                                                                                                                                                       | Accepted                                  | [ADR 0007](adr/0007-quotes-and-commercial-offers.md), [ADR 0008](adr/0008-configurable-monthly-billing-strategies.md)                                  |
| D-015 | Quote duplication carries over the source item's exact frozen monthly-billing snapshot verbatim (never re-reads current tenant settings)                                                                                                                                                                 | Duplication is defined (ADR 0007) as a faithful copy in a fresh DRAFT shell, not a re-quote; every other price field on a duplicated item is already copied verbatim, so the billing-strategy snapshot follows the same rule                                                                                                                   | Accepted                                  | [ADR 0007](adr/0007-quotes-and-commercial-offers.md)                                                                                                   |
| D-016 | Rental-number generation: replace the count-then-check pattern with an atomic, tenant-scoped `RentalSequence` counter (`INSERT ... ON CONFLICT DO UPDATE ... RETURNING`), mirroring the pattern already used for quote numbers                                                                           | The count-then-check pattern could produce colliding candidate numbers under concurrent requests; Postgres's `ON CONFLICT DO UPDATE` row-level lock makes the increment genuinely atomic without an application-level lock or unbounded retry loop                                                                                             | Accepted                                  | `rental-numbering.util.ts`; migration `20260730203437_add_rental_sequence`; [ADR 0009](adr/0009-shared-monthly-pricing-and-atomic-rental-numbering.md) |
| D-017 | Existing rental numbers are never renumbered; the new `RentalSequence` counter for each tenant is initialized from that tenant's current maximum parsed `RNT-######` number (or 0 if none/unparseable), so the next generated number cannot collide with history                                         | Migrations must never alter or lose existing financial/operational identifiers; a nonstandard or unparseable historical number is treated conservatively (ignored for counter initialization, left untouched on the row) rather than guessed at                                                                                                | Accepted                                  | Migration `20260730203437_add_rental_sequence` SQL comments; [ADR 0009](adr/0009-shared-monthly-pricing-and-atomic-rental-numbering.md)                |
| D-018 | `pdfkit` (not a headless browser) for PDF generation, with an embedded Unicode TTF for Cyrillic support                                                                                                                                                                                                  | Docker/CI reliability — a headless-Chromium dependency is heavier and flakier in this environment                                                                                                                                                                                                                                              | Accepted                                  | [ADR 0007](adr/0007-quotes-and-commercial-offers.md)                                                                                                   |
| D-019 | Public quote acceptance via a hashed, expiring, single-active opaque token on the `Quote` row (no separate token table)                                                                                                                                                                                  | Mirrors the existing `RefreshToken` hashing convention; avoids a second token model for a narrow use case                                                                                                                                                                                                                                      | Accepted                                  | [ADR 0007](adr/0007-quotes-and-commercial-offers.md)                                                                                                   |
| D-020 | A single generic `Document` model (tagged by a `DocumentType` enum) covers every business document type, with no type-specific columns — type-specific content lives entirely in untyped `businessDataSnapshot`/`dataJson` JSON                                                                          | A new document type must never require a schema change; mirrors the existing `AssetCustomFieldValue.valueJson`/`QuoteItemType.CUSTOM` "universal, not industry-hardcoded" pattern                                                                                                                                                              | Accepted                                  | [ADR 0010](adr/0010-document-management-platform.md)                                                                                                   |
| D-021 | `DocumentType.QUOTE` exists in the enum but the existing `Quote` module is not migrated or duplicated into `Document` rows in TASK-0008 Part 1                                                                                                                                                           | "Do not rewrite completed modules unnecessarily" — Quotes already has its own tested lifecycle, numbering, PDF, and public-token flow; a future bridge is possible once the new platform has proven itself, not attempted here                                                                                                                 | Accepted                                  | [ADR 0010](adr/0010-document-management-platform.md)                                                                                                   |
| D-022 | Whole-document versioning: a `DocumentVersion` is mutable only while its document is `DRAFT`; the moment status leaves `DRAFT` the version is finalized (`isFinal`, `finalizedAt`) and never edited again; corrections create a new parent-linked version and reset the document to `DRAFT`              | Business documents are framed as legal records — once finalized, a correction must be visible and traceable, never a silent edit; this is new architecture, since Quotes/Rentals only freeze pricing at the item level, never the whole record                                                                                                 | Accepted                                  | [ADR 0010](adr/0010-document-management-platform.md)                                                                                                   |
| D-023 | Four explicitly separated layers: Business Data (`DocumentVersion.businessDataSnapshot`), Template (`DocumentTemplate`, a bare registry with no rendering content yet), Rendering/Storage (`DocumentFile`, reusing `StorageService`), Version (`DocumentVersion` itself)                                 | The task explicitly required these never be mixed; keeping them as separate tables/columns now means template authoring and a rendering engine can be added later without touching the business-data or storage layers                                                                                                                         | Accepted                                  | [ADR 0010](adr/0010-document-management-platform.md)                                                                                                   |
| D-024 | Per-(tenant, documentType) atomic `DocumentSequence` counters, non-year-scoped for named business types (`CON-######`, `HD-######`, ...), year-scoped only for `CUSTOM` (`DOC-2026-######`); the `year` column uses a `0` sentinel instead of `NULL` for non-year-scoped types                           | Mirrors the proven `RentalSequence`/`QuoteSequence` atomic-upsert pattern (ADR 0009); a nullable `year` would silently break the `ON CONFLICT` upsert's atomicity since Postgres treats every `NULL` as distinct from every other `NULL`                                                                                                       | Accepted                                  | `document-numbering.util.ts`; [ADR 0010](adr/0010-document-management-platform.md)                                                                     |
| D-025 | No frontend UI, template rendering, or e-signature integration in TASK-0008 Part 1 — `sign`/`reject`/`markViewed` only record staff-asserted outcomes                                                                                                                                                    | The task explicitly scopes Part 1 to architecture/domain model and says not to build visual layouts; verified via 391 backend tests (31 new) and a real-database concurrency check instead of a manual browser walkthrough, since there is no UI to click through yet                                                                          | Accepted                                  | [ADR 0010](adr/0010-document-management-platform.md)                                                                                                   |
